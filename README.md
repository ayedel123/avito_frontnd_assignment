# BookRoom — бронирование переговорных

Фронтенд-приложение для бронирования переговорных комнат (Avito Frontend Trainee Assignment, осень 2026). Работает поверх предоставленного мок-бэкенда.

Позволяет выбрать офис, отфильтровать свободные комнаты по дате / времени начала / длительности / вместимости, посмотреть расписание конкретной комнаты на день, создать и отменить бронирование, а также следить за изменениями в реальном времени через WebSocket.

## Стек

**Ядро**
- **React 19** + **TypeScript**
- **Vite 8** — сборка и dev-сервер
- **TanStack Router** — файловый роутинг с автоматическим code-splitting
- **TanStack Query v5** — серверный кэш, мутации, оптимистичные обновления

**Данные и состояние**
- **Axios** — HTTP-клиент (единый инстанс, `baseURL = VITE_API_URL`)
- **Zod v4** — валидация ответов API (`safeParse`, бросаем ошибку при несоответствии схеме)
- **nuqs v2** — состояние фильтров в URL query-параметрах (офис, дата, время, длительность, вместимость, вкладки, диапазон дат)

**UI**
- **Tailwind CSS v4** (CSS-first, `@theme inline`), акцентный цвет — розовый (`--primary`)
- **shadcn-ui** — базовые ui компоненты
- **lucide-react** — иконки

**Real-time**
- Нативный **WebSocket** к `/api/v1/ws` с авто-reconnect и ресинком кэша

**Тесты**
- **Vitest** + **@testing-library/react** + **jsdom** — юнит- и снапшот-тесты
- **@vitest/coverage-v8** — покрытие

## Запуск

Нужен **Node.js ≥ 20**.

### 1. Бэкенд (мок)

```bash
cd server
npm install
npm run dev        # поднимается на http://localhost:3000
```

### 2. Фронтенд

```bash
cd front
npm install
npm run dev        # http://localhost:5173
```

Фронт обращается к бэкенду напрямую по `VITE_API_URL`. Мок-бэкенд разрешает CORS для `http://localhost:5173`, поэтому прокси Vite не нужен. Для локального запуска переменную можно не задавать — есть фолбэк на `http://localhost:3000/api/v1`.

### Переменные окружения (`front/`)

Переменная — `VITE_API_URL` (базовый URL API). Пример и описание — в [`front/.env.example`](front/.env.example):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | `http://localhost:3000/api/v1` | Полный URL API мок-бэкенда. Из него же строится адрес WebSocket (`http` → `ws`). |

## Архитектура

FSD-lite, импорты только «вниз»: **`shared` → `entities` → `features` → `routes`** (слоя `widgets` нет).

- **`shared`** — переиспользуемые тулзы и «глупый» UI: axios-инстанс, `cn`, работа с таймзонами (`toIsoWithOffset`, `getDateBounds`, `getTodayInTimeZone`, `parseAsLocalDate`), экспорт `.ics`, shadcn-компоненты.
- **`entities`** — доменные сущности с их API, Zod-схемами, типами и дата-хуками: `office`, `room` (+ расписание), `booking`, `user`, `rooms-filter`. Ключи запросов (`QK_*`) лежат рядом с самими запросами.
- **`features`** — пользовательские сценарии: `rooms-list`, `room-schedule`, `book-room`, `cancel-booking`, `bookings`, `sync`.
- **`routes`** — файловый роутинг TanStack Router.

Роуты: `/` → редирект на `/rooms`, `/rooms` (каталог), `/rooms/$roomId` (расписание комнаты), `/bookings` (мои брони), плюс `notFoundComponent` (404).

### Ключевые решения

- **Состояние фильтров — в URL.** Через `nuqs`: ссылку можно расшарить/перезагрузить. Кнопка офиса в шапке — прямая ссылка на `/rooms` с выбранным офисом. (Сознательно не тащили Zustand: под дедлайн URL-state покрывает потребности; «идеал» — стор + синхронизация в query — оставлен за скобками.)
- **Оптимистичная отмена** брони с откатом: `onMutate` убирает бронь из кэшей, `onError` восстанавливает снапшот, `onSettled` инвалидирует. `staleTime`/`gcTime`.
- **Рабочие часы** — единый конфиг `shared/config/workday.ts`: рабочий день **09:00–20:00**, шаг 15 минут, окно бронирования 30 дней вперёд. Значения совпадают с ограничениями бэкенда (`booking-rules.ts`), поэтому фильтры, пикеры и таймлайн расписания не дают выбрать интервал, который бэк отклонит.
- **Повторяющиеся бронирования** (`features/recurring-booking`) — у бэка нет понятия серии, поэтому это N обычных броней. Бэк не даёт бронировать дальше 30 дней (`BOOKING_TOO_FAR_AHEAD`), так что при создании серии все вхождения в пределах 30 дней создаются сразу,ошибки в запросах пропускаются с тостом), правило серии сохраняется в `localStorage`. При старте приложения добронируются те даты, что уже вошли в 30дневное окно, и флаг сдвигается дальше.
- **Адаптивная вёрстка** Всеми функциями приложения можно пользоваться на любых размерах экрана, но приоритет отводился экранам планшетов и пк, интерфейс на смарфонах может быть не вполне корректен с точки зрения эстетики, но приложение остаётся рабочим и все функции доступны

## Чего не делал

- **Адаптивная / мобильная вёрстка** — интерфейс рассчитан на десктоп, под узкие экраны и тач-устройства не адаптировался.
- **UI управления сериями** повторяющихся броней — правило живёт в `localStorage`, пока не будет удалено вручную (функция `removeRule` есть, кнопки нет).
- Повторяющиеся брони не учитывают чужие брони на тот же слот — конфликт (`409`) просто пропускается.
